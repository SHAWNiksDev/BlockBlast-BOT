# Как бот получает состояние игры

## Текущий режим

Бот получает изображение телефона через USB и ADB. По сетке поля, цветовым различиям и граням кубиков он определяет занятые клетки и формы фигур. Отдельный планировщик рассчитывает ходы. После жеста бот проверяет, что игра действительно приняла фигуру.

Поле и ходы обрабатываются обычными алгоритмами, ключи API и облачные сервисы не нужны. OCR применяется отдельно — для чтения очков и рекорда. Tesseract использует локальную обученную модель; она не выбирает ходы. Проверенная модель поставляется с проектом, поэтому результат не зависит от языкового пакета системы. Если OCR недоступен, бот продолжает играть и показывает неизвестные значения.

При смене оформления образец фона и порог выделения фигур вычисляются заново. Блоки дополнительно проверяются по граням, поэтому цвет не является единственным признаком. Стабильность позиции подтверждается несколькими кадрами. Переключать тему в настройках бота не требуется.

## Почему пока нет режима «из памяти»

Обычный доступ ADB не даёт права читать память другого приложения. Также нельзя заранее предполагать, что игра записывает текущее поле и все фигуры в доступный файл: часть состояния может жить только в процессе игры.

В релизе нет режима чтения памяти. Доступ к памяти и внутренним файлам игры требует отдельной разрешённой среды и исследования формата состояния.

Для рабочего второго режима понадобится отдельная среда с разрешённым доступом к процессу — например, эмулятор с root — и исследование структуры состояния именно этой версии игры. Наличие root само по себе ещё не даёт готового формата поля. После обнаружения такого формата можно реализовать отдельный адаптер и проверить его на реальной игре. Разблокировка загрузчика, установка root, изменение APK и переустановка игры в эту работу не входили.

Описание изоляции приложений: [Android Application Sandbox](https://source.android.com/docs/security/app-sandbox).
