# BlockBlast BOT

Бот для классического Block Blast на Android: распознаёт поле и фигуры, планирует размещения, управляет телефоном через ADB и проверяет результат каждого жеста. Есть Qt-интерфейс на русском, английском и украинском языках и консольный режим.

Версия 0.3.1. [Скачать программу](https://github.com/SHAWNiksDev/BlockBlast-BOT/releases/latest) · [Изменения](CHANGELOG.md) · [Подробности работы](docs/STATE_SOURCES.md).


## Запуск готовой программы

1. Скачайте архив для своей системы со страницы релиза и распакуйте его целиком.
2. Подключите телефон по USB. В настройках телефона включите отладку по USB и подтвердите подключение к компьютеру.
3. Откройте классическую партию Block Blast на телефоне.
4. Запустите `BlockBlast BOT.exe` на Windows или `BlockBlast BOT` на Linux, выберите телефон и нажмите «Начать».

| Система | Архив |
| --- | --- |
| Windows 10/11, 64 бита | `BlockBlast-BOT-windows-x86_64.zip` |
| Linux x86_64, glibc 2.39+ | `BlockBlast-BOT-linux-x86_64.tar.gz` |

Python и внешние инструменты для готовой сборки устанавливать не нужно. Не вынимайте EXE из распакованной папки: рядом нужны `_internal`, `tools` и `profiles`. На Windows некоторым телефонам нужен USB-драйвер производителя. На Linux нужны системные права USB. Личного профиля телефона в поставке нет. Перед игрой проверьте распознавание и откалибруйте жесты.

Настройки сохраняются рядом с программой. Распаковывайте архив в обычную доступную для записи папку, например в «Документы», а не в `Program Files`.

Бот подстраивается под оформление игры и проверяет результат жестов. Поле и фигуры распознаются по изображению обычным алгоритмом, очки читает OCR. Для выбора ходов нейросеть не нужна; подписка и отправка кадров в облако не используются. Режим чтения памяти игры в этой версии не реализован: на обычном телефоне Android закрывает такой доступ.

## Запуск из исходников

На Windows создайте окружение командой `python -m venv .venv`, установите зависимости через `.venv\Scripts\python -m pip install -r requirements-desktop.txt` и запустите `run-gui.cmd`. Для исходников нужны доступные через PATH ADB, FFmpeg и Tesseract 5+.

Нужны Linux, Python 3.10+, ADB и разрешённая USB-отладка на телефоне. Для видеопотока нужен FFmpeg, для чтения очков — Tesseract 5+. Проверенная модель цифр уже входит в проект. Без FFmpeg режим `auto` использует скриншоты; без Tesseract бот работает без очков.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-desktop.txt
adb devices
./run.sh
```

Откройте классическую партию на телефоне и выберите устройство в окне бота. Новую партию и рекламу бот автоматически не запускает. Собранный portable-вариант запускается из всей папки дистрибутива, рядом с `_internal`, `tools`, `profiles` и `settings.json`.

## Профиль телефона

`profiles/default.json` — пустой профиль для автоматического поиска поля. Параметры конкретного телефона не поставляются. Перед игрой требуется проверка распознавания и калибровка жестов. Проверить распознавание без жестов:

```sh
./run.sh doctor
./run.sh inspect
```

Поля профиля:

| Поле | Значение |
| --- | --- |
| `screen_size` | Разрешение телефона `[width, height]` |
| `board` | Границы поля `[left, top, right, bottom]` |
| `tray` | Область трёх равных слотов фигур |
| `tray_cell` | Шаг маленьких блоков в лотке |
| `drag_gain` | Усиление перемещения фигуры относительно пальца |
| `lift_cells` | Подъём фигуры над пальцем в клетках поля |
| `release_bias_cells` | Поправка точки отпускания |
| `color_distance` | Порог отделения фигур от фона |
| `score_box`, `record_box` | Необязательные области чисел |

Геометрия профиля задаётся в координатах полного экрана. Распознавание и OCR учитывают масштаб видеопотока. При отсутствии `screen_size` используется масштаб, записанный захватом в кадр; автоматический поиск поля работает с пустым профилем, но точность жестов всё равно требует калибровки.

## Консольный режим

```sh
./run.sh play --moves 50
./run.sh play --serial SERIAL
./run.sh play --profile profiles/default.json
./run.sh play --capture screenshot
./run.sh play --no-score --no-screenshots
./run.sh play --no-logs --no-board
./run.sh settings --set max_moves=0 --set capture=auto
./run.sh --help
```

Без аргументов `run.sh` открывает GUI. `run-gui.sh` также запускает GUI. `--moves 0` означает отсутствие лимита. Лимит учитывает подтверждённые ходы. Ctrl+C или кнопка «Остановить» завершают запуск с доступной статистикой.

При серии отклонённых жестов GUI ждёт кнопки «Продолжить». Консольный запуск завершается с сообщением проверить экран и запустить бота заново. Выход из приложения, шторка и ручная пауза при включённом `auto_pause` пережидаются без новых жестов.

## Захват и проверка ходов

Режим `auto` использует H.264-поток Android screenrecord и при сбое переходит на скриншоты с последующими попытками восстановить поток. `stream` требует поток; `screenshot` использует отдельные PNG через ADB. Записи на телефоне не создаются. Поток публикует последний кадр в родном разрешении; координаты пересчитываются в координаты телефона.

Перед ходами бот проверяет доступность игры. После жеста сверяет поле и оставшиеся фигуры. Временное согласование проверяет накопленное движение фигуры за окно наблюдения. Неожиданная устойчивая позиция может быть принята с пересчётом плана.

Если распознанный лоток остаётся пустым в течение всего тайм-аута и хотя бы 1,5 секунды стабилен, запуск завершается с предложением проверить игру. Сам пустой лоток не объявляется доказательством проигрыша. Нераспознаваемые меню при `auto_pause=true` по-прежнему пережидаются до возвращения игры или остановки пользователем.

При смене позиции или возобновлении бот проверяет возможное начало новой партии: снижение счёта подтверждается двумя чтениями при неизменной распознанной позиции. Подтверждённая смена партии завершает сессию перед следующим жестом, сохраняя статистику старой партии. При недоступном OCR изменение доски во время паузы также требует нового запуска. Определить любую смену партии без доступных визуальных признаков невозможно.

## Настройки

Настройки хранятся в `settings.json` рядом с программой и применяются при следующем запуске. При отсутствии файла используются значения по умолчанию; первое сохранение создаёт файл. Личные настройки исключены из Git и архива исходников. CLI переопределяет их для одного запуска. Тема и язык в GUI сохраняются сразу; игровые настройки доступны между сессиями.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `max_moves` | 0 | Лимит подтверждённых ходов |
| `beam` | 180 | Ширина поиска |
| `capture` | auto | Способ захвата |
| `stream_width`, `stream_fps` | 540, 12 | Размер и частота потока |
| `stable_frames`, `settle_time` | 3, 0.2 | Согласование кадров |
| `verify_timeout`, `animation_timeout` | 5, 15 | Ожидание подтверждения/анимации |
| `max_rejections` | 5 | Порог защитной остановки/паузы после отказов |
| `read_score`, `score_every` | true, 3 | OCR и интервал чтения |
| `file_logs`, `console_logs` | true, true | Запись истории и показ событий |
| `save_screenshots` | false | Сохранение изображений |
| `max_sessions`, `max_history_mb` | 50, 100 | Количество и общий объём истории |
| `max_screenshots`, `max_log_mb` | 20, 2 | Снимки и ротация JSONL |

Полный перечень и допустимые значения — в `blockblast/config.py`. Ручные пресеты скорости удалены. `--delay` регулирует интервал диагностической проверки результата, а не разрешает ход без подтверждения.

## История и ограничения хранения

В `logs/run-*` сохраняются ротируемый `events.jsonl`, сжатая хронология `timeline.jsonl.gz` и итоговый `summary.json`. Снимки сохраняются только при включённом параметре. `stats.json` содержит общую статистику и записывается через временный файл с атомарной заменой.

Лимит истории проверяется перед записью, включая текущую сессию. Старые сессии удаляются первыми. Если активная сессия заполняет бюджет, запись новых событий и снимков отключается с уведомлением; игра продолжается. Существующая хронология сохраняется, для итоговой сводки резервируется место. После достижения лимита файловая хронология неполная. Ошибки создания/записи хранилища также не прерывают игру; при недоступном диске файловый отчёт может отсутствовать.

Лимит относится к известным папкам сессий, а не к размеру исходников, дистрибутива или произвольных файлов. Независимые процессы не разделяют транзакционную квоту диска. При `file_logs=false` и `save_screenshots=false` сессия не записывает историю. В GUI отключённая история также отключает снимки.

```sh
./run.sh clean --screenshots-only --dry-run
./run.sh clean --screenshots-only
./run.sh clean
```

Очистка предназначена для остановленного бота и удаляет только известные сгенерированные файлы. Настройки, тестовые примеры и общая статистика сохраняются.

## Стратегия и проверки

Движок использует 64-битную доску, перебирает порядок фигур, одновременно очищает строки/столбцы без гравитации и оценивает свободное место для крупных фигур. Дополнительный поиск помогает, если основной не нашёл размещения всей тройки. Поиск ограничен; оптимальность и бесконечное выживание не гарантируются. Эвристика не заменяет точную формулу очков: реальные числа читает OCR.

```sh
QT_QPA_PLATFORM=offscreen python3 -m unittest discover -s tests -q
python3 audit/reproduce.py
```

Тесты проверяют движок, паузы, Qt-интерфейс, захват, хранилище и пограничные сценарии. Частные PNG-примеры и проверки, зависевшие от них, удалены. Проверка OCR готового пакета использует сгенерированное изображение. Реальную игру на своём устройстве можно проверить через `scripts/qa_device.py` после калибровки.

Подробности: [сборка и проверки](docs/RELEASE.md), [источники состояния игры](docs/STATE_SOURCES.md).
